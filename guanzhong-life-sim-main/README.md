# 象贤人生 · 高中三年模拟器

以 **广州市番禺区象贤中学**（1826 年沙湾古镇留耕堂内的"象贤家塾"，校训"象贤砺业"）为背景的高中三年人生模拟器。网页游戏，支持**联机**（排行榜 / 全校动态 / 云存档），也支持**纯本地单机**。

## 怎么跑

### 方式一：本地服务器（推荐，可联机）
```bash
cd xiangxian-life-sim
node server.js
```
然后浏览器打开 http://localhost:3000 （Windows 也可以直接双击 `start.bat`）。

- 同一局域网的同学访问 `http://<你的IP>:3000` 即可一起玩，排行榜动态共享
- 数据存在 `./data/` 目录（排行榜 / 动态 / 存档），删掉即重置

### 方式二：纯本地单机（单文件）
直接双击 `xiangxian-life-sim.html`（项目根目录，CSS/JS 已内联，零依赖）即可开玩。`file://` 下检测不到服务器，自动进入**单机模式**：图鉴、剧情、结局全部照常，主菜单会提示「单机模式 · 排行榜与全校动态不可用」。

也可以直接双击 `public/index.html`，效果一样。

### 方式三：发布到公网
把项目根目录作为单端口 HTTP 服务发布（`server.js` 已监听 `process.env.PORT` 并绑定 `0.0.0.0`），得到一条分享链接，谁点开谁能玩。

### 方式四：内网穿透（跑在自己电脑上）
不想依赖托管平台、想让数据留在本机，就把本地 3000 端口穿透到公网。项目里备了两个双击即用的脚本：

| 脚本 | 原理 | 需要下载 |
| --- | --- | --- |
| `tunnel.bat` | Cloudflare 快速隧道（`cloudflared tunnel --url`） | `cloudflared.exe`（放 `%USERPROFILE%\cloudflared\`） |
| `tunnel-ssh.bat` | SSH 反向隧道（`localhost.run`，备选 `serveo.net`） | 无，用 Windows 自带的 OpenSSH |

两个脚本都会先检查 3000 端口：已经在监听就复用，没在监听就自动 `node server.js` 起一个。

**注意**

- **不需要改防火墙**。隧道是 `cloudflared` / `ssh` 主动向公网建**出站**连接，公网流量顺着这条连接回来，所以没有入站规则问题（这点和局域网直连不同）。
- 链接**每次重启都会变**，发出去之前记得重新看一眼窗口里打印的地址。
- 那个窗口**必须一直开着**，关掉即失效；电脑休眠/关机也会断。
- 免费隧道在**国内网络下可能慢或不稳**，这是服务本身的限制，不是游戏的问题。真要长期分享，方式三更省心。

## 界面说明

- 当前视觉恢复为旧版移动端的**米白纸张 + 深绿色主色 + 橙色剧情强调**：主菜单有校徽、校训、名字/性别/走读住宿/天赋/班级/难度一页式开局表单。
- **性别会决定走哪条恋爱线**：选「男」走女生篇，选「女」走男生篇（见「恋爱线」章节）。
- 游戏内 HUD 保留睡眠、社交、学习、**好感度**、校区、居住方式、班级、头衔等信息，只改成更紧凑的顶部属性栏。好感度那一条会显示当前对象名下的好感数值与阶段（未遇见时显示「—」）。
- 事件卡和选项现在属于同一条可滚动的**剧情流**：最新事件刷新在顶部，旧事件依次留在下方，从下往上看就是旧 → 新；主选择、校园事件选择和恋爱选择始终固定在剧情流底部。
- 底部保留并常驻显示「📢 校园动态」：连续展示社交月、睡眠月、一起学习、考试排名、学习月及对应属性变化；动态过多时在面板内滚动，不会挤走图鉴、排行榜、自动推演三个入口。

### 名字输入：不允许卡在第一步

「点得动按钮但打不出字」报了三次，前两次都在加兜底、没找到根因（用 jsdom 复现，而且直接给 `value` 赋值——**绕过了真实键盘路径**，所以一直是假阳性）。第三次换成 `puppeteer-core` 驱动真实 Chrome，走真实鼠标 / 触摸 / 按键，才抓到两个**真实 bug**：

**Bug ①：中文输入法的回车被当成「直接开局」。**
中文输入法用回车 / 完成键**确认候选词**。原代码无条件把任何回车都当开局，于是玩家拼音还没上屏就被推进学期开场——表现就是「名字根本打不进去」。
修法：`compositionstart/end` + `event.isComposing` + `event.keyCode === 229` **三重放行**（`isComposing` / `229` 是各浏览器通用的「正在组词」信号，再加 `compositionstart/end` 兜住个别不设 `isComposing` 的 WebView）。

**Bug ②：切屏不重置滚动位置，名字栏被顶到视口外。**
手机上主菜单很长（玩法说明一大段），玩家要滑到底部才点得到「开始高中」。设置页沿用了上一屏的 `scrollY`（实测 `240`），一进来就是滚到中间的，名字输入框落到 **`y = -76`**——在视口上方，看起来就像「没有名字栏」。
修法：`show()` 里调 `resetScroll()` 归零；进设置页再 `scrollIntoView({ block: 'center' })` + `focus()`，把键盘直接弹出来。

三层兜底仍然保留（针对其它环境的键盘问题，与上面两个 bug 独立）：

1. **进设置时强制解锁输入框**：`unlockNameInput()` 清掉可能残留的 `disabled` / `readonly` / `aria-disabled`。
2. **🎲 随机取名**：完全不依赖键盘，点一下就能拿到名字。
3. **留空也能开局**：直接点「开启三年人生」会自动分配一个名字并继续，**不再用 `alert` 拦截**（弹窗在部分内嵌面板里会被忽略甚至抛异常）。

配套的样式收敛：输入框只保留最基础的属性，去掉了 `position: relative; z-index: 2` 这类可能在个别 WebView 上弄坏点击热区的写法；`.screen` / `.panel` / `#screen-game` 的高度加了 `100dvh` 兜底，避免手机键盘弹出时布局跳动把输入框顶走。另外整块 `.field` 可点聚焦、打字时有实时反馈（`#name-hint` 会回显「好，就叫「XX」。」）。

回归覆盖：`test-name-input.js` 用**真实 Chrome**跑 13 项断言（滚动归零 / 输入框在视口内 / 自动聚焦 / 三种组词信号各测一次 / 组词确认后回车正常开局 / 触摸打字 / 🎲 / 留空开局 / 两种 iframe 内嵌）；`runtime-probe.js` 与 `single-runtime-probe.js` 各有对应场景，另覆盖「完全不打字、直接开局」这条路径。

## 联机功能

前端会主动连接 `server.js` 的接口，连不上就静默降级成单机，不会报错、不影响游戏本体：

| 功能 | 说明 |
| --- | --- |
| 在线人数 | 每 45 秒一次心跳，主菜单实时显示「已联机 · 当前在线 N 人」 |
| 全校排行榜 | 主菜单「🏆 全校排行榜」，取 `/api/leaderboard` 前 30 名，自己那条会高亮 |
| 全校动态 | 主菜单「📢 全校动态」，取 `/api/feed` 最近 30 条，显示相对时间 |
| 成绩上榜 | 高考放榜时自动 POST 成绩，结局页显示「全校排名 第 N 名」，同一个人只保留最高分 |
| 事件播报 | 关键节点自动往全校动态发一条：开局入学 🎒、拿到头衔（卷王/学神/黑马/恋爱脑/小丑/六边形战士…）、强制休学 🏥、高考放榜 🎓 |

> 动态是**只读**的，前端没有开放自由发帖（避免被人刷屏）；所有播报都由游戏事件自动触发。
> `data/feed.json` 与 `data/leaderboard.json` 会随项目一起上传，所以本地玩出来的记录会出现在线上榜单里；不想公开就先清空 `data/` 再发布。

### 接口

| 路径 | 方法 | 说明 |
| --- | --- | --- |
| `/api/health` | GET | 存活探针，返回 `uptime` / `pid` / `node` / `rss`。**`uptime` 归零说明进程崩过重启了** |
| `/api/hello` | GET | 探测服务器是否存在，返回当前在线人数 |
| `/api/heartbeat` | POST | 心跳，45 秒一次 |
| `/api/leaderboard` | GET / POST | 取前 30 名 / 提交成绩 |
| `/api/feed` | GET / POST | 取最近 30 条动态 / 播报一条 |
| `/api/save` | GET / POST | 云存档（当前前端未使用） |

### 服务端抗崩措施

公网分享时最容易踩的坑是「一个人用过之后，所有人都进不来了」，成因有三类，都已处理：

1. **socket 错误升级成未捕获异常**：访客关页面 / 切网络时连接中断，往死掉的 socket 写数据会抛错。现在每个请求都挂了 `req.on('error')` / `res.on('error')`，所有写出统一走 `safeWrite()`（先判 `writableEnded` / `destroyed`）。
2. **未处理的 Promise 拒绝**：Node 15+ 默认直接终止进程。现在请求处理器整体包了 `try/catch`，并加了 `unhandledRejection` / `uncaughtException` / `server.on('error')` / `server.on('clientError')` 四重兜底。
3. **反向代理复用 keep-alive 连接**：Node 默认 5s 关掉连接，代理若仍拿这条死连接转发下一个请求就会 502。现在 `keepAliveTimeout = 65s`、`headersTimeout = 66s`。

另外静态文件统一 `Cache-Control: no-store`，避免浏览器把新旧 `index.html` / `game.js` 混着用导致白屏。

> 单机模式下这些入口照常能点开，只是会提示连不上服务器。

## 玩法

- 象贤中学完整走完高中三年六个学期，每月选一次重心：**睡眠 / 社交 / 学习**（也可开"自动推演"挂机）
- 每月还会追加**一个日常时间点的小抉择**（早读 / 课间 / 午饭午休 / 放学 / 晚修 / 晚修后 / 周末循环），外加 5% 概率的随机小事件，见下面的「日常选项」章节。
- 开局可选**难度**，见下面的「难度」章节：默认 **困难 +1**，另有一档更高难度的 **炼狱 +2**。
- 开局选择**住宿生 / 走读生**：住宿生进入宿舍线，走读生不吃饭堂但可以从校外带早餐、带外卖进校（都可能被查）。
- 校区与校历：高一高二在旧校区，男生宿舍 12 人间；高三在新校区，男生宿舍 10 人间。高一高二周六中午放学，高三周六下午放学，周日下午 7 点回校。
- 每月还有**周末剧情**和**夜修后宿舍/回家剧情**；学校偶尔被征用为社会考试考场，只征用高一高二教室，通常周五下午高一高二提前放学，高三照常上课。高三可以趁学弟学妹放假一起混出去。
- 高一上学期结束、进入高一下学期时进行 **3+1+2 选科**（物理类 / 历史类），之后影响考试与结算。
- **开局天赋**：学霸胚子（学习 +15）/ 社交达人（社交 +15）/ 心态大师（睡眠 +15），只加起步属性，和恋爱线互相独立。
- **恋爱线**：开学第 2 轮「遇见」选对象，之后按好感度推进 9 段主线；**开局性别决定走哪条线**（男 → 女生篇，女 → 男生篇）。恋爱剧情约占全部剧情的 1/3。
- **高三升学线**：高三会遇到模考周、高三冲刺和志愿填报；高考后根据实际分数展示清北、985/强 211、双一流、一本、本科或专科/继续准备等大学结局。
- **时间线与真实世界对齐**：开学年按真实日期定死（9 月及以后入学算当年，1—8 月算上一年），六个学期严格对应真实校历月份，节日按真实公历 / 农历日期触发，高考固定在 6 月 7—9 日，详见下面的「真实校历」章节。
- **学校开放日**：在 12 月、3 月、5 月对应的真实月份各触发一次学校开放日事件，分别影响社交、学习和睡眠；普通校园事件仍会照常出现。
- **选科适配度**：女生学物理、男生学历史，选科后「学习优先」的收益会降低 3 点（选科界面会提示）；课堂和晚修都可以玩手机，但年级主任 / 级长抓得很紧，高三宿舍查得松。
- **睡眠分级**：低于 80 进入疲惫，低于 70 对学习和生活产生明显影响；低于 60 有概率特殊情况强制休学 1 个月，低于 50 有概率特殊情况强制休学 1 年，睡眠越低触发概率越高。
- **学习成绩映射**：学习 <45 为年级末流（高考预计 470 以下）；45～55 为中游（470～530）；55～70 为中上游（530～570）；70～100 为前沿（570～690）。高三同样学习属性在考试中会因为竞争加剧而排名更低，但不会直接扣学习属性；最终高考实际分数按难度额外下降（困难 10～30 分，炼狱 18～42 分）。

## 真实校历（时间线对齐真实世界）

游戏里的日期不是随便编的月份标签，而是**真的和现实日历对得上**。整局覆盖 **30 个学术月份**、跨 **3 个学年**，从「高一上学期 9 月」走到「高三下学期 6 月高考」。

### 学期与月份

| 学期 | 月份 |
| --- | --- |
| 高一上 / 高二上 / 高三上 | 9、10、11、12、1 月 |
| 高一下 / 高二下 / 高三下 | 2、3、4、5、6 月 |

**7、8 月不会出现**——寒暑假不在校历里，这和真实高中一致。月内再按轮次切成「上旬 / 下旬」（90 轮制 3 轮一月，60 轮制 2 轮一月，30 轮制 1 轮一月）。

### 起始年怎么定

`CFG.startYear` 在**开局那一刻**按真实日期算一次，然后**跟着存档一起保存**（不存的话跨年读档日期会漂）：

- 9 月及以后开局 → 入学年 = 当年（例：2026 年 9 月入学）
- 1—8 月开局 → 入学年 = 上一年（因为还属于上一个学年）

于是 **2026 年 9 月入学 → 2029 年 6 月 7—9 日高考**。高考日期按广东 3+1+2 新高考的固定安排（6 月 7—9 日），结局页与志愿填报事件都会显示真实年份。

界面上三处都会带上真实年月：

- HUD 标题：`高一上学期 · 2026年9月上旬`
- 学期栏：`2026—2027 学年 · 第 1 / 6 学期 · …`
- 学期开场：`📅 本学期：2026年9月 — 2027年1月`

### 节日

节日分成两类，**全部按真实日期落在对应的学术月份上**：

| 类型 | 节日 | 说明 |
| --- | --- | --- |
| 固定公历 | 元旦 1/1、劳动节 5/1、国庆节 10/1 | 每年一样 |
| 逐年变化 | 春节、清明节、端午节、中秋节 | 取真实农历换算 / 国务院节假日安排 |

农历表 `REAL_LUNAR_FESTIVALS` 覆盖 **2026—2031 年**（数据来源：2026 年取国务院节假日安排通知，2027—2031 年按农历换算）。**超出范围的年份只推固定公历节日，绝不瞎编农历日期**——这样即使游戏被跑到 2032 年之后，也只是少几个节日，不会出现「春节在 7 月」这种假数据。

一个学术月份可能**同时撞上两个节日**，这时合并成一条事件、属性求和后做上下限截断（`clamp(-3, 5)`）：

- 2028 年 1 月 = 元旦 + 春节（1/26）
- 2028 年 5 月 = 劳动节 + 端午节（5/28）
- 2028 年 10 月 = 国庆节 + 中秋节（10/3）

每个节日**一局只触发一次**（记在 `S.flags.festivalsSeen`）。全程 90 轮制下共触发 **18 条**节日事件。

### 连带被修好的东西

改之前的老实现是拿「总轮次」硬映射 20 个月份标签，**和学期完全脱钩**：高一下学期第一轮会显示成「12月上旬」，越往后越漂（高一的 1 月显示成 11 月、高一下的 2 月显示成 12 月……）。而下面这些全都靠 `phaseFor()` 取月份，所以**一起错了**：

- 生日、情人节（2/14）、圣诞节（12/25）、男生篇校际比赛日（10 月）
- 学校开放日（12 月 / 3 月 / 5 月）

现在它们取到的都是真实月份。改造时特意**保留 `phaseFor()` 的输出形状**（仍以 `9月` / `12月` 开头、仍能被 `parseInt` 取出月份），因为上面这些功能是 `parseInt` / `startsWith` 取月份的——换形状会把它们全打断。

回归覆盖：`test-calendar.js`（三种轮制下的年月映射、18 条节日落点与去重、同月撞两节合并、高考日期、`phaseFor` 向后兼容）；`runtime-probe.js` / `single-runtime-probe.js` 各有一个场景在**真实 DOM** 上核对 HUD 年月、学期栏学年与节日事件确实进了事件流。

## 难度

难度在**开局设置**里选，两档都集中在 `DIFFICULTY_PRESETS` 里，改一处即可同时影响全局。

| 项目 | 困难 +1（默认） | 炼狱 +2（更高难度） |
| --- | --- | --- |
| 考试间隔 | 每 5 轮 | 每 4 轮 |
| 睡眠优先收益 | +11 睡眠 / −3 社交 / −4 学习 | +10 睡眠 / −4 社交 / −5 学习 |
| 排名中心后移 | +8 | +22 |
| 高三竞争扣分 | 10～30 分 | 18～42 分 |
| 休学概率倍率 | ×1.0 | ×1.35 |
| 低睡眠强制休整回补 | +6 睡眠 | +3 睡眠 |
| 好感增长倍率 | ×1.0 | ×0.7 |

炼狱档的实现要点：

- `DIFFICULTY` 从原来的冻结常量改成 `DIFFICULTY_PRESETS` + `setDifficulty(key)`，`CFG.difficulty` 会随存档一起保存，旧存档一律按困难恢复。
- `sleepLeaveChance()` 乘上 `leaveChanceMul`，所以炼狱档睡眠掉到同样水平时休学概率更高。
- `mainEffects()` 继续按 `level` 线性缩放，`examRankForStudy()` / `computeScore()` 改读 `rankOffset` / `gaokaoPenalty`。
- 好感增长用 `scaleAff()` 做**随机取整**（向下取整 + 按余数掷骰），所以炼狱档下 `+1` 这种小额度也不会被四舍五入直接吞掉。

## 日常选项（寄宿制高中的一天）

和「本月安排」**完全并行**的一层：每个月除了三选一的大方向，还会追加**一个时间点的小抉择**。原有事件、原有主选择路径一行都没动，日常选项只是往事件队列里多推一张卡。

### 七个时间点循环

`S.dailyIdx` 递增取模 7，依次推进，跑完一圈回到早读：

| 时间点 | 选项数 | 内容 |
| --- | --- | --- |
| 🌤️ 早读课前 | 4 | 晨读背书 / 补作业 / 趴桌补觉 / 走廊闲聊 |
| 📖 课间 | 5 | 趴桌小憩 / 办公室答疑 / 操场走一圈 / 脚滑车改装 / 聊天打闹 |
| 🍚 午饭 & 午休 | 3 | 吃饭午休 / 教室刷题 / 出校探店 |
| 🌇 放学之后 | 5 | 操场 / 提前写作业 / 社团活动室 / 校史馆散步 / 饭堂唠嗑 |
| ✍️ 晚修时段 | 4 | 刷题整理错题 / 传纸条 / 偷偷看课外书 / 发呆摆烂 |
| 🌙 晚修结束，回宿舍 | 2 | 早睡 / 台灯下刷题 |
| 📅 周末放假 | 4 | 埋头刷题 / 约同学出来 / 社团外出 / 睡到自然醒 |

共 **27 个选项**，只影响 **睡眠 / 社交 / 学识** 三项属性。内部沿用 `study` 字段，靠 `DAILY_FX_LABELS = { study: '学识' }` 把显示名从「学习」换成「学识」——**不传这个参数时行为与改动前完全一致**，所以原有事件一点没变。

### 概率型结果

部分选项带「小概率翻车」分支（走 `resolve()`，和原有校园事件同一套机制）：

- 早读趴桌补觉：25% 被值班老师点名 → 睡眠 +1 / 学识 -1 / 社交 -1
- 课间聊天打闹：30% 被班干部提醒安静 → 只剩睡眠 -1
- 晚修专心刷题：40% 遇到难题心态崩了 → **无属性加成**
- 早睡：30% 失眠 → **属性不变**

### 外出假

- **走读生**随时可以「出校探店」。
- **住宿生**需要一张外出假：周末选「约同学见面 / 社团外出 / 出门逛街」时拿到，出校探店时消耗。
- 状态存在 `S.flags.dayPass`，由 `dailyCanLeave()` / `dailyGrantLeavePass()` / `dailyUseLeavePass()` 管理。

### 校史秘闻

「逛校园，去校史馆和老校舍附近散步」每次随机给 **+3 点属性**（睡眠 / 社交 / 学识 之一），并累计一条校史线索（共 5 条）。集齐 `DAILY_LORE_NEED = 3` 条解锁隐藏成就 **「校史秘闻」**。

### 🎲 随机小事件（5%）

每轮有 `DAILY_RANDOM_CHANCE = 5%` 的概率额外触发一个小事件，同样是日常卡：

| 事件 | 选项 |
| --- | --- |
| 班主任安排你负责班级黑板报 | 答应接下任务 → 社交 +2 ／ 委婉推辞 → 无加成 |
| 月考临近，同桌找你要笔记复习 | 大方借给他 → 社交 +3 ／ 婉拒，自己还要用 → 社交 -1 学识 +3 |

### 不影响恋爱占比

日常选项**不计入恋爱剧情配额**（不调用 `loveQuotaTick()`），所以它只是「多出来的内容」，恋爱占比仍然稳定在 1/3。

> 日常卡在事件流里显示为 **🕒 日常 · 学期**，模块配色用蓝灰描边（`.daily-choice-module`）与「剧情选择」区分开。


## 恋爱线（好感度五阶段）

> **恋爱剧情约占全部剧情节点的 1/3**，由下面的「恋爱剧情配额」闭环控制，实测各难度各时长都稳定收敛在 32%～33.5%。

恋爱线是**独立系统**，不绑开局天赋。开学第 2 轮会出现「🚪 遇见」事件，从 4 位性格完全不同的同学里选一个作为对象，之后按好感度推进 9 段主线。

### 两条线：男玩家走女生篇，女玩家走男生篇

**开局选「男」→ 攻略对象是女生；开局选「女」→ 攻略对象是男生。** 两条线是**并行两套完整内容**，共用同一套好感度框架与同一组主线门槛，只换文案表、称呼表与成就键。

| 维度 | 女生篇（男玩家） | 男生篇（女玩家） |
| --- | --- | --- |
| 心动方式 | 通过「被照顾的细节」累积 | 通过「并肩做事 / 一起扛事」累积 |
| 情绪表达 | 直接说出感受，或明显躲闪 | 用行动代替语言，话到嘴边变成别的事 |
| 示好手段 | 留位置、带早餐、发消息 | 修东西、较劲、绕远路、把好东西分你一半 |
| 吃醋表现 | 直接问「那个女生是谁」 | 沉默、突然变得很客气、打球特别凶 |
| 告白特征 | 说得很轻、说完就低头 | 说得很直、说完盯着你的眼睛等答案 |
| 被拒方式 | 温和、留余地 | 逞强、「我们不是挺好吗」、然后自己走掉 |

实现上是**路线分流层**：`loveRoute()` 返回 `'girl'`（男玩家）/ `'boy'`（女玩家），所有文案表都通过 `loveChars()` / `affStages()` / `loveStoryList()` / `loveChatTable()` / `loveMsgTable()` / `dateSpots()` / `dexLoveItems()` 这类访问器取表。**女生篇的所有文案与数值保持原样**，男生篇是新增的平行分支（`test-e2e.js` 会断言两条线的成就键互斥、对象名不串味）。

| 阶段 | 好感 | 关系标签（女生篇 / 男生篇） | 玩家可见描述（女生篇） | 玩家可见描述（男生篇） |
| --- | --- | --- | --- | --- |

**没告白之前好感封顶在 90**，不会自动变成恋人——必须走「💗 告白」事件并且选对选项才会进入恋人阶段。告白失败不会锁死剧情，好感重新涨回 90 还能再试一次；但**毕业时还没告白，这条线就永久关闭**，进入遗憾结局（女生篇「无言的夏天」／男生篇「没说出口」）。恋人状态一旦确认，不会被一次负面事件撤销，只有分手事件能解除。

### 恋爱剧情配额（把恋爱压到 1/3）

`buildEventQueue()` 每轮会产出一个「校园事件 + 恋爱事件」的组合。为了不让恋爱内容吃掉整局，恋爱部分由一个**令牌桶**闭环控制：

- 每产出一个校园事件，配额 `+1` 点；每触发一次恋爱事件，消耗 `2` 点。
- 因此长期「恋爱 : 校园」稳定在 `1 : 2`，**恋爱占比收敛到 1/3**。
- 遇见 / 节日 / 主线这些**必推节点不受抽签限制**（它们有门槛、总量也少），但**照样消耗配额**——所以主线连着推的那几轮，日常恋爱内容会自动让位。
- 配额攒满（`LOVE_QUOTA_CAP = 4`）时不再抽签、直接消耗，避免恋爱线长时间缺席。
- 反过来，如果必推节点扎堆导致占比已经超标，本轮会**补 1 个校园事件稀释**（每轮最多补 1 个），把占比拉回 1/3。

配额状态存在 `S.loveQuota = { tokens, campus, love }`，`loveRatio()` 给出实际占比，结局的「游玩记录」里会显示，`test-e2e.js` 也用它做断言。

实测（`test-e2e.js` 7 局：男玩家 3 局 / 女玩家 4 局，含 30 / 60 / 90 轮与两档难度）：合计 恋爱 125 / 全部 381 = **32.8%**，各局区间 32.1%～33.3%。日常选项不参与配额，所以加入后占比没有变化。
